Budget Analyser UX Guide

Colours, type and component styles used in the Budget Analyser WPF app. The app follows Material Design in a single dark theme, built on MaterialDesignInXamlToolkit plus the app's own dictionaries under BudgetAnalyser/UI/Style.

This page is a visual reference. The XAML stays the source of truth, so update this page in the same commit as any style change.

Last updated: 2026-09-27 Matches branch claude/ux-material-design at Phase 5 (colour palette) Plan: ux-material-design-plan.md

Principles

These come from the Material Design plan and should guide every new screen.

Dark theme only

The app has no light theme. Pick every colour for a near-black background, and check its contrast there.

A small palette

The app uses four hues: teal, green, red and orange. Each hue has a light tone for text on surfaces and a container tone for fills. Don't add new hues.

Colour carries meaning

Green means positive or credit, red means negative or debit, orange means "needs attention", and teal is the brand and interactive colour. Never use colour just for decoration.

Keep it simple

The app keeps a tab strip, one content area and a modal overlay. Motion stays at toolkit defaults (ripple and elevation). Don't add drawers, sheets or gestures.

Rule of thumb: on a container (coloured) fill, use only TextHigh or white. Medium-emphasis text and light hue tones are only readable on the grey surfaces.

Surfaces & elevation

On a dark theme, higher surfaces are lighter, as well as casting a shadow. Cards use the toolkit's ElevationAssist.Elevation, so don't hand-roll DropShadowEffect on new elements.

0dpPage
1–2dpPanels · tiles (Dp2)

The tab strip is the one exception. It uses a small DropShadowEffect (blur 6, depth 2, 50% black) pointing down onto the content.

All buttons are based on the toolkit's MaterialDesignRaisedButton or MaterialDesignFlatButton, and have rectangular 4px corners. Pressing a button shows the Material ripple. Styles live in Buttons.xaml.

Toolbar icon buttons (Button.Round.*)

These are 40×40 PrimaryContainer buttons with a white glyph and a tooltip. They are still named "Round" for compatibility, but they're rectangular now. The glyph is set through ContentTemplate, never through a Content setter, because a shared UIElement would only render in one button.

Add · Minus · Save · Left · Right · Cross · Lock · All · disabled. There are also Build, Clear, Info, PlusL/PlusR, ApplyRules, EditRules, SmallCross, TransferFunds and Unlock. The glyphs shown here are stand-ins for the app's vector assets.

Square text button

Tab strip

This is the TabButtonStyle in MainMenuUserControl.xaml, a Material top-app-bar tab. It's flat with a 3px Primary underline on the active tab and a Primary ripple on press. Hovering a tab raises its label to high emphasis.

Each tab is 48px high, at least 120px wide, with padding 16,0 and gap 4. The first tab has a 12px left inset. Inactive labels use Text.Disabled and the active label uses Text.Default.

Do / Don't

Do

  • Reference semantic Brush.* keys from views.
  • Base new control styles on a toolkit style with BasedOn.
  • Put only TextHigh or white text on a container fill.
  • Use the light hue tones for amounts and icons on grey surfaces.
  • Use ElevationAssist.Elevation for depth.
  • Reserve orange for "needs attention" and red for "wrong or overspent".
  • Update this guide in the same commit as a style change.

Don't

  • Hard-code hex colours in views (only ScratchPad.xaml does, and it's a scratch file).
  • Add a new hue, or a third tone of an existing hue, without updating the palette and this guide.
  • Rename brush or tile keys that C# looks up by string.
  • Use light tones (Primary, Positive, Negative) as fills behind text.
  • Use Text.Medium or Text.Disabled on coloured fills.
  • Add custom DropShadowEffects or bespoke animations.
